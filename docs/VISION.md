# 产品愿景

## 一句话

PatchAtlas 是面向 Java 开源仓库的 **Issue-to-Test 验证平台**：它在看不到人类修复的前提下，把一个 Issue 转成候选回归测试，再通过隔离环境中的跨版本执行，判定该测试是**真的复现了缺陷**，还是编译错误、环境问题或 flaky 噪音。

## 要解决的问题

模型写代码已经很便宜，**判断它写得对不对仍然很贵**。

对缺陷而言，判断的前提是复现。维护者收到 Issue 后的第一件事是"我能不能复现"，大量 Issue 就停在这一步。而一旦有了能复现缺陷的测试，后续的修复才有了可机械判定的验收标准——测试也因此可以反过来充当候选补丁的过滤器。

PatchAtlas 只做这一步，并且把它做成**可审计的证据**而不是模型的自我声明。

## 产品能力

三层能力各自独立可交付：

### Replay Engine

在隔离环境中对指定 Revision 执行同一测试，产出结构化执行事实，并把失败归入明确类别：编译失败、环境失败、目标断言失败、超时、flaky、两侧同时失败。它不依赖模型，可独立演示与校准。

### Issue2Test

系统的核心。受限 Agent 依据 Issue 与缺陷版本定位相关代码、生成候选测试，全过程不得接触 Fixed Revision、人类修复差异或已知触发测试。成功率诚实度量并公开成败——**真实缺陷上成功率可能不高，这是测量结果，不是需要掩饰的事**。

### 影响分析

依据代码关系图，给出一次改动波及的方法、直接调用方、相关入口与测试关联，每条结论带影响置信度分级。它首先服务于候选测试的上下文选择，也作为独立能力对外提供。

## 什么算成功

只有当同一个候选测试在**缺陷版本上因目标断言失败**、在**修复版本上通过**，且排除编译、环境、超时与偶发失败之后，系统才输出「复现成功」。

尚无修复版本的真实 Issue 只能得到「疑似复现」，等待修复版本完成最终验证。

系统在证据不足时必须说"无法判定"，**不得用一个看起来完整的结论替代**。这条纪律贯穿全部输出：价格未知时不显示为零，覆盖率不可得时标注不适用，定位未完成时记录预算耗尽。

## 非目标

非目标分三类。**"永远不做"与"暂时不做"不得混为一谈。**

### 1. 永久安全红线（任何版本都不做）

- 执行任意 Shell 命令；
- 把密钥带入构建容器或泄露到日志、指标、报告中；
- 在不受限的宿主环境中执行目标仓库的构建；
- **模型无监督地直接修改生产源码、构建脚本或 CI 配置**。

### 2. 定位排除（长期非目标）

这些不是做不到，而是做了会让产品失焦：

- 登录体系与多租户；
- Kubernetes、消息队列、Redis 等为水平扩展引入的基础设施；
- MCP 等对外协议暴露；
- 运行时的多 Agent 编排。

### 3. V1 后置（当前版本不做，之后再评估）

- GitHub App 与自动评论；
- Gradle 支持与多语言仓库；
- 自动修复——且**仅限"生成补丁 → 人工审查"的受控形式**，模型无监督改生产源码永远属于第 1 类红线；
- 架构规则生成。
