# 架构决策记录（ADR）

本目录记录 PatchAtlas 中**难以逆转、脱离上下文会让人困惑、且来自真实权衡**的决策。三条同时成立才立 ADR；缺任何一条就写进 `docs/architecture.md` 即可。

## 编号规则

- **只有一套编号：`ADR-NNN`**，三位数字，连续递增，不复用、不回收。
- 文件名为 `ADR-NNN-<英文短横线标题>.md`。
- 结构固定：状态 / 日期 / 背景 / 决策 / 考虑过的替代方案 / 后果。
- 被取代的决策**保留原文**，把状态改为「已被 ADR-NNN 取代」，不删除、不原地改写。

## ⚠️ 遗留：`AD-xxx` 与 `ADR-xxx` 编号撞车

历史上存在第二套编号 `AD-xxx`，用来指代架构原则。它与本目录的 `ADR-xxx` **含义不同但编号重叠**，例如：

- `AD-002` 指「事实与模型判断分离」
- `ADR-002` 指「在 Buggy 侧预验证后提交唯一候选」

这两者毫无关系。`AD-xxx` 从未在 `docs/` 下定义过，只在代码注释与本地规划文档中被引用，因此是一组**悬空引用**。

已知的对应关系：

| 旧编号 | 指代的原则 | 现状 |
| --- | --- | --- |
| `AD-002` | 事实与模型判断分离 | 内容在 `docs/architecture.md`，待提升为 ADR |
| `AD-004` | 影响置信度分级 | 内容在 `docs/architecture.md` 与 `docs/domain-language.md`，待提升为 ADR |
| `AD-006` | 预言机隔离 | 内容在 `docs/architecture.md`，待提升为 ADR |
| `AD-007` | 训练数据污染控制 | 内容在 `docs/architecture.md` 评测原则，待提升为 ADR |
| `AD-005` | 未知 | 无任何定义留存，若无人能还原则直接废弃 |

**迁移约定**：

1. 新决策一律使用 `ADR-NNN`，**不得再新增 `AD-xxx` 编号**；
2. 上表中的原则按需逐条提升为正式 ADR，提升时在本表标注新编号；
3. 代码注释与规划文档中的 `AD-xxx` 引用在对应 ADR 落地后一并替换——**该替换属于代码改动，不在文档批次内完成**。
