# 图引导对照的预先声明解释

对照实验开始前先把每种观测对应的解释写死，避免看到数字再挑选说法。本表在冻结 Spring 使用队列之前定稿，之后不得改写。

图引导定位要检验的是：在使用 Spring 的项目上，沿调用图边的 `expand` 会不会被用到、用到是否节省定位成本。选样只按 buggy revision 的 `pom.xml` 依赖是否使用 Spring，不按这次修复是否需要遍历。

| 观测 | 预先声明的解释 |
| --- | --- |
| `expand` 仍然 0 次 | 沿边遍历不是模型会主动使用的能力。这是工具设计或提示词的问题，不能据此声称「图没有信息量」。要么提高 `expand` 的可发现性，要么承认该用法在此场景不成立。 |
| `expand` 被使用，且图臂调用更少或读得更准 | 支持图引导；收益应归因到轨迹里实际走过的边类型。 |
| `expand` 被使用但没有节省或更准 | 图能被用到，但不带来定位收益。这是有价值的负面结果，照实报告。 |
| 合格冻结成员不足 4 例 | Java/Spring 生态缺少可按本系统闸门机械复现的公开缺陷数据。这本身是对数据源的观察，写进报告，不为凑数放宽闸门。 |
