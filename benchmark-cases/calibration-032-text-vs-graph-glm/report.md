# 文本工具与图工具定位调用成本对照（glm-5.2）

日期：2026-08-18  
端点：`https://ollama.com/v1`  
模型：`glm-5.2`  
测量预算：60 次工具调用 / 15 分钟墙钟（两臂相同）

| 臂 | 目录 |
| --- | --- |
| B · `TEXT_TOOLS`（`search` / `list` / `read` / `submit`） | `benchmark-cases/calibration-032-text-tools-glm/` |
| A′ · `GRAPH_TOOLS`（`find` / `expand` / `read` / `submit`） | `benchmark-cases/calibration-032-graph-tools-glm/` |

两臂共用冻结队列 6 例 × 3 次、同一 `read`/`submit` 实现、同一提示词骨架（只换工具描述段）。`agnes-2.5-flash` 的文本臂记录见 `benchmark-cases/calibration-027-tool-budget/`，换模型后不可比。

本对照只报调用成本、发现阶段调用次数、`read_not_submitted`、ToolError 率、建图开销。**不计算定位命中率，也不比较谁找得对。**

## 采样是否完整

两臂都跑满 18 / 18，全部到达 `SUBMIT`。均未触发停止条件：无人触到放宽上限 60，传输失败 0，N>8 守卫未触发，进分位数会话分别为 16 与 17（均 ≥12）。

图臂 18 次建图全部成功；轨迹中无 `SEARCH` / `LIST` / `UNKNOWN_TOOL`，没有标着图工具实际跑文本工具的臂。

采样前各做了 whatsapp#100 与 jsoup#2002 的单会话确认：文本臂走 `search`/`list` → `read` → `submit`，图臂走 `find` → `read` → `submit`。

## 调用次数（进分位数）

进分位数 = 到达 `SUBMIT` 且轨迹中没有 `BUDGET_WARNING`。p50 / p95 用含端点线性插值，算法与 `calibration-027-tool-budget` 相同。

| | B 文本 | A′ 图 |
| --- | --- | --- |
| 进分位数 n | 16 | 17 |
| 有警告的 SUBMIT | 2（均为 47） | 1（48） |
| 调用次数（升序） | `[4, 5, 6, 7, 7, 8, 9, 9, 10, 10, 11, 11, 14, 23, 27, 37]` | `[5, 6, 6, 9, 10, 10, 11, 12, 13, 13, 14, 15, 16, 17, 18, 38, 38]` |
| **p50** | **9.5** | **13** |
| **p95** | **29.5** | **38** |
| **max** | **37** | **38** |

本样本里图臂的 p50 / p95 / max 都不低于文本臂。这是调用次数，不是对错。

时长（进分位数，秒，含克隆工作区）：文本 p50 = 21.5 / p95 = 49.75；图 p50 = 21.9 / p95 ≈ 68.2。图臂墙钟含建图之前的克隆，建图本身不扣测量预算。

## ToolError 率（分工具）

已执行工具 = 发现工具 + `read` + `submit`。`GRAPH_BUILD` 与 `BUDGET_WARNING` 不计。

| 步骤 | B OK / ERROR | A′ OK / ERROR |
| --- | --- | --- |
| SEARCH | 85 / 0 | — |
| LIST | 16 / 0 | — |
| FIND | — | 145 / 0 |
| EXPAND | — | 0 / 0 |
| READ | 171 / 0 | 129 / 0 |
| SUBMIT | 18 / 2 | 18 / 7 |
| **合计** | **290 / 2** | **292 / 7** |
| **ERROR 率** | **2 / 292 ≈ 0.68%** | **7 / 299 ≈ 2.3%** |

两臂的 ERROR 都是 submit 闸门拒绝，不是发现工具或 `read` 抛错：

- 文本：jsoup#2002 第 1 次 `file exceeds 64 KiB`；ConfigMe#363 第 2 次超过 12 条路径。
- 图：jsoup#2002 三次 `file exceeds 64 KiB`；ConfigMe#363 第 2、3 次超过 12 条路径。

同会话随后都再次提交并被接受。

## 建图开销（仅 A′）

建图在工具循环之前。耗时不扣 60 次预算、不扣 15 分钟测量墙钟；失败则整次会话协议失败，不改用文本工具。本样本 18 / 18 成功。

| 项 | 值 |
| --- | --- |
| 缓存命中 | **14 / 18**（约 78%） |
| 全样本耗时 p50 | **66 ms** |
| 未命中 | 4 次：274、979、1435、2321 ms |
| 命中 | 14 次：2–121 ms |

whatsapp#100 与 jsoup#2002 第 1 次命中，是因为采样前的单会话确认已写入同一缓存。其余四个修订各未命中一次，之后全命中。

## 不在本对照里的问题

生产定位预算仍是 35 次 / 9 分钟（按 `agnes-2.5-flash` 定的）。本对照不改那个常数。

本文件没有「图更好 / 文本更好 / 定位更准」的结论。要回答那些问题需要 Oracle Data，不在这次采样的范围内。
